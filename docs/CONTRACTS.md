# Contract register

This register is the durable module ownership and change-control boundary. It records all 36 catalog modules. It
does not mark later milestone behavior as implemented.

## How to read the register

Contract source entries use three states:

- **Frozen** means a callable type, trait, route, or facade exists and current
  consumers may compile against it.
- **Implemented** means the named production behavior exists and is exercised
  through its listed contract or focused behavior tests.
- **Browser-free test seam** means a literal fixture or serialization check
  implements only a declared unit boundary; it is not a browser API or fallback.
- **Reserved** means this register row is the current frozen contract and names
  an unsupported or future boundary. A reserved entry is not evidence that the
  source file or behavior exists.

Owners are plan roles, not permanent people. One role owns each contract.
Consumers lists direct component consumers. Local Stack Deployment consumes the whole system
and is implicit in every row unless it is the only consumer.

## Blueprint and instance courses

`BlueprintCourse` and `CourseInstance` are the two PLE course types.
`BlueprintCourse` owns reusable course content and structure. It has no Students,
live deadlines, releases, accommodations, grades, or delivery settings.
`CourseInstance` is created from a Blueprint Course and owns enrollment,
deadlines, releases, accommodations, grades, and delivery settings for one live
teaching context.

A newly added Blueprint assignment propagates to its daughter Course Instances
as unreleased. Release is an explicit instance decision; propagation does not
silently release the assignment. ADAPT's alpha-course language is comparison
vocabulary only. PLE defines no `AlphaCourse` product type or compatibility
alias.

Every assignment item resolves to an already published question in the one
approved-Instructor Question Library. Here, published means discoverable and
resolvable within that vetted Instructor audience across its lifecycle; it does
not mean anonymous internet access. Subject tags classify questions without
partitioning the Question Library.

Immutable migration filenames and registered external protocol field names keep
their historical or owner spelling for lineage and interoperability. They are
metadata, not contract authority: a filename such as
an old migration filename or an external scope field
does not establish an installation scope. Current PLE-owned contracts use the domain
owners above and the typed worker/object scopes.

## Deferred QTI profile-to-PLE contract

QTI parsing is an available adapter boundary, while its private authoring,
profile-worker, conversion, and PostgreSQL acceptance composition are deferred
with the Store-backed delivery surface. The resulting route and worker chain
must authorize an existing Authoring Workspace before opaque ZIP bytes are
read, project only an answer-free report, and commit an acknowledged accepted
item atomically as one complete PLE Question JSON Draft Question. The original
QTI package, profile, item reference, mappings, warnings, and checksums remain
Workspace Import evidence. The ordinary backend-agnostic Draft Question and
publication operations own every later step.

The browser report remains answer-free. A future connected acceptance lane must
cover mixed accepted and rejected imports, private authoring authorization,
exact conversion, cleanup, and Workspace Import evidence retention against
disposable PostgreSQL. The parser-owned adapter
code remains under [crates/adapters/qti/](../crates/adapters/qti/); the
former browser-only QTI workflow has been removed. A future QTI import surface
must arrive with its exact Workspace Import Store and service route.

## Course appearance contract

`crates/question_model/src/course_appearance.rs` owns the frozen browser-safe appearance vocabulary.
It defines the 15 closed biome and habitat theme IDs, with `grass` as the only default; explicit
decorative or validated informative banner text; opaque Course Banner and upload references; and
the safe current `CourseAppearanceView`. Generated TypeScript runtime values and the union derive
from this Rust owner, including `coral-reef`, `salt-marsh`, and `sea-floor`. Unknown IDs refuse.

When present, the browser-safe current Course Banner has exactly `{ reference, alternativeText }`.
Its `reference` resolves only through the same-origin delivery route; the direct Course Banner
contract does not use a generic `id` property or a separate presentation wrapper.

`CourseAppearanceView` is exactly `{ theme, banner }` for an authorized route reader. Theme and
Banner are stored independently and have independent mutations: `CourseThemeUpdate` replaces the
scalar Theme, while a Course Banner Upload is staged and then promoted, replaced, or removed through
the Banner boundary. There is no appearance revision, `If-Match` precondition, combined save, or
appearance history.

The View and Course Banner Upload receipt contain no Object Address, bucket, checksum, filename, source bytes,
upload metadata, signed URL, Answer Key, Question Feedback, Question Answer
Explanation, Question Grading Input, or answer-bearing type. Course identity is route-owned.
`CourseBannerUpload` and `CourseBanner` Object Addresses have no caller-supplied paths: uploads are
temporary and non-signable, while saved banners remain private content until an exact Course record
authorizes delivery.

The registered no-store reader authorizes every active Course Member; the Theme and Banner writes
authorize only an active Instructor Course Member. Anonymous callers, nonmembers, and foreign
Instructors receive the same concealed refusal. A Banner Upload is bound to its exact Course,
Instructor, expiry, and server-owned object identity; decoded PNG, JPEG, or WebP bytes are validated
before its two-phase source and derived-rendition promotion. One private source and both lossless
WebP deliveries--a 1200 by 200 hero and 1000 by 400 card--must complete before the Course's current
Banner changes. Uncertain external work remains in the persisted cleanup/repair saga. No appearance
operation is a Wasm export.

The route-scoped theme registry and safe `CourseRouteView` carry no Object Address, checksum,
filename in JSON, signed URL, Question Answer, Answer Key, Question Feedback, Question Answer
Explanation, or Question Grading Input.

Dedicated authorized C-reference navigation and member Course Summary reads are direct-route
prerequisites; neither creates a second appearance model. The strict decoder accepts only the 15
generated IDs; unknown theme IDs are contract failures and never silently fall back.

**Owner.** `crates/question_model/src/course_appearance.rs` owns browser-safe values;
`crates/learning-data-access/src/{course_theme.rs,course_banner.rs}` own the separate persistence
boundaries; and `crates/server/src/course_appearance.rs` owns the registered authorization and HTTP
routes.

`AssignmentRevisionNumber` has one domain authority at
`crates/question_model/src/assignment/revision.rs`. Its JSON wire value is a canonical positive
base-10 string bounded by PostgreSQL `BIGINT`; zero, leading zeroes, signs, whitespace, and values
above that range are rejected. An `AssignmentRevisionReference` pairs that number with its exact
`AssignmentReference`, matching the fresh schema's immutable Assignment Revision boundary. Strong
assignment `If-Match` validators carry the same decimal value inside the repository's quoted ETag
grammar. Learning-data-access owns only checked conversion to and from stored `BIGINT` values.

Every teaching `CourseRecord` and browser-safe `CourseSummary` carries mandatory `shortName` and
`longName` Course Instance names, plus one mandatory `CourseTerm`: inclusive, ordered `startDate`
and `endDate` calendar dates only. The shared question-model value types own calendar parsing and
term ordering. Course Instance creation accepts only `{blueprintCourse, blueprintRevision,
shortName, longName, term: {startDate, endDate}, assignedInstructor?}`; malformed or unknown
fields do not persist a course, and correctable term failures use the bounded generated 422
contract. PostgreSQL preserves both names on the Course Instance root and the two calendar bounds
on the Course Schedule Revision, while strict browser decoders reject any absent or malformed
name or term. There is one course-term authority.

An Instructor supplies zone-free local schedule input. The authenticated Instructor Account's exact
IANA zone interprets it after the local calendar date has been checked against `CourseTerm`; DST gaps
and ambiguities remain refusals. Stored schedule values are instants, so later reads and displays do
not impose a second, fictional Course clock. Preview and Blueprint schedule operations use the
acting Account zone at their existing authority boundary.

The Course Banner image contract accepts decoded PNG, JPEG, or WebP source bytes after orientation.
The server preserves one private source and derives centered, lossless WebP hero and card renditions
at 1200 by 200 and 1000 by 400 respectively. Browser surfaces select only these fixed renditions;
they never supply a storage identity or arbitrary crop.

## Automated-grading operations contract

G1 keeps saved Student input, final submission, private execution, evaluation,
and Instructor-visible recovery as separate contracts. The current Student
delivery boundary is the caller-owned public `R-n` Assignment Attempt:

```text
PUT  /api/assignment-attempts/{attempt}/responses/{position}
POST /api/assignment-attempts/{attempt}/submission
```

The response-save route validates presentation-scoped references, translates
them to canonical server-side input, and returns an answer-free `no-store`
saved-state acknowledgement. The whole-Attempt submission route has no request
body. It succeeds only when every issued position has a saved response, then
atomically creates immutable per-Question submission and grading work. Its
`no-store` acknowledgement contains the public Attempt reference and submitted
state; a missing response receives the bounded validation refusal.

Native PLE retains a distinct, status-only route:

```text
GET /api/course-instances/{course}/assignments/{assignment}/presentations/{nonce}/submissions
```

It returns only the presentation nonce and grading state. This read is not a
Student answer-submission endpoint: the former Course/Assignment/Attempt POST
submission shape is not registered, and whole-Attempt finalization owns
immutable submission creation.

The assignment-local Instructor operations routes are:

```text
GET  /api/courses/{course}/assignments/{assignment}/grading-operations
POST /api/courses/{course}/assignments/{assignment}/grading-operations/{operation}/retry
POST /api/courses/{course}/assignments/{assignment}/grading-operations/recalculate
```

They are `no-store` and metadata-only. List rows contain bounded question or
student grouping plus assignment-wide recalculation rows, safe reason and
state, revision, trust generation, and a safe next action. POST actions have
empty bodies and require `If-Match`; the server and Store recheck current Instructor Course Membership authority,
the authenticated `account_id`, exact `course_id`, and `assignment_id` in the transaction.
Responses and receipts
never contain responses, answer keys, private source, feedback internals, or
score values.

Current Instructor Course Membership authority means the authenticated session has the Instructor
role, the account has an active Instructor Course Membership in the requested
`course_id`, and the operation's assignment is a child of that course. Student, outsider, or
browser-supplied role and membership values do not satisfy this contract.

`AcceptedSubmissionExecutionWorker` owns private claim, load, grading, and
tuple-fenced commit/fail for the accepted-submission execution boundary. The exact
synchronous path and background recovery use the same handler and validated
lease/deadline contract. The existing assignment recalculation enqueue in
migration `2026081830` and current-score publication in `2026081831` remain
the only score path.

## WeBWorK renderer contract

PLE uses the external standalone `webwork-pg-renderer` service, not a browser
API, the retired PLE `/v1` dialect, or the WebWork2 homework application. The
bounded client posts server-owned immutable PG/PGML source, source path, Question Seed,
display policy, and resolved answer to `/render-api` as form data. Renderer JWT
state, upstream answer fields, source, and credentials remain server-only.

The response parser accepts the standalone service's closed JSON shape,
validates request and renderer identity, and projects recognized controls into
opaque PLE response options. Redirects, non-JSON responses, duplicate or
unexpected members, malformed markup, unsafe resources, and unsupported
controls refuse. The browser receives only the typed PLE Question Presentation and submits a
PLE response through the same-origin API.

`containers/compose.yaml` runs the external renderer on `renderer_private` with
no host port, SQL database, or persistent volume. The typed lifecycle records its OCI
image identity and runs `containers/webwork/probe_render_api.sh` before API
startup. The bounded licensed `RadioButtons` path passed its original live acceptance on
2026-08-10; the four reviewed Chapter 1 PGML sources, including matching partial credit, passed the
real renderer and built-browser release path on 2026-08-11. The detailed wire contract is
[WEBWORK_PG_RENDERER_API_USAGE.md](WEBWORK_PG_RENDERER_API_USAGE.md).

## Frozen-contract change rule

A frozen contract change must land atomically. The same patch must:

1. update this register;
2. update the owning source contract;
3. update every direct consumer named in that row, including any bounded test double;
4. regenerate derivative types or fixtures through their owning generator;
5. update conformance, secrecy, parity, or browser evidence affected by the
   change; and
6. record the behavior or decision in `docs/CHANGELOG.md`.

A contract change without every consumer is blocking. Do not merge a producer
first and repair consumers in later lane patches. Additive wire changes still
follow this rule because exhaustive TypeScript unions and Rust matches can make
an apparently additive variant a consumer-breaking change.

## Boundary invariants

- Apply the repository-specific boundary naming matrix in
  [NAMING_CONVENTIONS.md](NAMING_CONVENTIONS.md). PLE-owned serialized fields and portable
  discriminant values and TypeScript PLE data-object properties use `snake_case` end to end.
- Rust modules, functions, and fields use snake case; Rust types and variants
  use upper camel case. **Current pre-WN1:** routes still include direct lower-camel transport.
  **Approved target:** Serde owns snake PLE fields/discriminants and `tsgen` emits one direct
  generated `Foo` with the same properties. Raw wasm-bindgen exports retain their native spelling
  at `src/wasm/index.ts`; feature decoders reject unknown, retired-camel, and invalid PLE input.
- Question Grading is server-only. It may never enter the Question Model Wasm dependency closure,
  generated browser types, test payloads, or client source.
- Learning Data Access's typed PLE Question JSON private-integrity check is a server-only exception to
  the usual storage/domain direction; it may not make Question Grading, grader pools,
  private bytes, or grading decisions reachable from Question Model Wasm. The browser
  closure remains `wasm_bridge`, `domain`, and `question_model` only.
- Published Questions use one global stable Question Library identity per lineage. Educational records carry direct
  `course_id`, `student_record_id`, `assignment_id`, `assignment_attempt_id`,
  `issued_question_id`, or `question_attempt_id` ownership as applicable and cross only a
  server-authorized boundary.
- The Assignment-owned `StudentFeedbackReleaseRule` independently controls score,
  per-item correctness, Question Feedback, Question Answer, Question Answer Explanation,
  and class statistics
  disclosure. The server evaluates those fields only after Active Student Course Membership,
  using S3's current effective policy and authoritative time; withheld fields
  are omitted. `QuestionAttemptLimit` is a retry bound only.
- Student aggregate routes are future work. Their prepared key-free
  `StudentAssignmentProgress` contract nests activity-only `AssignmentProgress`
  and disclosed `StudentAssignmentGrade`; its `NoActivity`, `Withheld`, and
  `Available` states prevent the browser from inferring a score.
  `AssignmentProgressRecord` remains an internal activity
  read-only activity state, while `AssignmentGrade` owns the selected course result. When the independently evaluated `class_statistics`
  field is disclosed, its optional `class_statistics` value is a key-free,
  policy-free, identity-free union: `unavailable` contains no metrics;
  `available` contains only `completed_student_cohort_size` and normalized
  `assignment_average_score`. Withheld class statistics are omitted.
- List contracts use bounded cursors. No public contract introduces an offset
  or an unbounded list operation.
- A newly issued parameterized Question Attempt receives a fresh server-owned Question Seed.
  Resume, re-render, audit, and debugging of that same attempt reuse its stored
  Question Seed and Question Attempt Reproduction Details. API-minted Question Seeds stay within JavaScript's exact integer
  range even though the internal generator accepts the full Rust `u64` domain.
- Successful HTTP bodies enter TypeScript as `unknown` and pass exhaustive
  null-prototype, closed-field decoders before becoming generated browser types. The client uses no
  `any`, unchecked assertion, caller-supplied authority selector, or cross-origin API base.
