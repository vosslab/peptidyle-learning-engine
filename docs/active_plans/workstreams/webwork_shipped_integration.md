# WP-RC3 shipped WeBWorK integration

## Status

Accepted on 2026-08-10 after live PLE/browser acceptance, WP-ARCH1's permanent size boundary, and
the final independent review. This workstream replaces PLE's invented renderer dialect with the
authenticated upstream WeBWorK
`render_rpc` protocol. It is
the executable contract for WP-RC3 in the
[release_completion_plan.md](../active/release_completion_plan.md#wp-rc3-integrate-upstream-webwork-as-shipped).
It follows the server-only grading and immutable-source rules in
[HUMAN_GUIDANCE.md](../../HUMAN_GUIDANCE.md). It does not stage, commit, reset,
or discard the mixed user-owned worktree.

This document is retained acceptance evidence for the historical RC3 compatibility path, not the
current runtime design. WP-RC3R now implements the external stateless `webwork-pg-renderer` path and
removes the WebWork2 application, render-course credential, and MariaDB. The strict source,
projection, grading, cache, outage, and browser-secrecy requirements remain reusable migration
oracles. `OTHER_REPOS/` is reference-only throughout.

## Required protocol behavior

1. The adapter builds a `POST` form for `/render_rpc` from server-owned settings only. The source is
   base64 in `problemSource`; `fileName` is immutable metadata, not a readable server path.
2. Render uses the immutable attempt seed. Grade repeats the render first, confirms the same configured
   identity and supported radio shape, maps the submitted opaque PLE choice ID to the newly parsed
   upstream field/value, and performs a second bounded `WWsubmit=1` form request.
3. The adapter sends no browser-selected URL, credential, upstream session key, persisted set/problem
   selector, `rawProblemSource`, `uriEncodedProblemSource`, correct-answer/debug flag, LTI grade
   passback field, or arbitrary form field.
4. The parser verifies expected echoed hidden RPC fields against its request, discards them, and refuses
   an extra or mismatched protected field. It permits neither scripts, event attributes, forms, frames,
   arbitrary external resources, nor unsafe URI schemes in the browser projection.
5. Render cache records only the sanitized answer-free envelope, sanitized HTML, trusted source/version/
   seed binding, and configured renderer identity. It never records an answer, a radio field name/value,
   source bytes, credential, cookie, session key, or raw RPC body.

### Pinned source build

- Fetch and detached-checkout `https://github.com/openwebwork/webwork2.git` only at
  `c7060fe858cb27b17aad5cf77574ff7d1ae3e1fa`.
- Fetch and detached-checkout `https://github.com/openwebwork/pg.git` only at
  `726ff42840f968a1d6dfcc270c23c297e1d963f4`.
- Require `git rev-parse HEAD` to equal the corresponding 40-hex value before the OCI build. Record
  the resulting image digest in the live-gate evidence and make the adapter's configured renderer
  identity derive from those two revisions plus that digest.

### Default JSON response schema

The upstream default JSON object admits these top-level keys exactly once:

- `head_part001`, `head_part010`, `head_part300`, `head_part400`, and `head_part999`.
- `body_part001`, `body_part100`, `body_part300`, `body_part500`, `body_part530`, `body_part550`,
  `body_part590`, `body_part650`, `body_part700`, and `body_part999`.
- `hidden_input_field`, `score`, `real_webwork_SITE_URL`, `real_webwork_FORM_ACTION_URL`, and
  `internal_problem_lang_and_dir`.

Project only `body_part550` and `score`. The configured `real_webwork_SITE_URL` is the origin root
`http://webwork-renderer:8080/`; `real_webwork_FORM_ACTION_URL` is the exact application path
`http://webwork-renderer:8080/webwork2/render_rpc`. Verify both exact values, then discard them.
Validate `hidden_input_field` directly as a JSON object, not as HTML `<input>` markup. Its complete
exact key map is: `sourceFilePath`,
`problemSource`, `problemSeed`, `problemUUID`, `psvn`, `pathToProblemFile`, `courseID`, `user`,
`passwd`, `displayMode`, `key`, `outputformat`, `theme`, `language`, `showSummary`, `showHints`,
`showSolutions`, `showPreviewButton`, `showCheckAnswersButton`, `showCorrectAnswersButton`,
`showFooter`, and `extraHeaderText`. Verify request-owned `problemSource`, `problemSeed`,
`pathToProblemFile` against the outgoing `fileName`, `courseID`, `user`, `passwd`, `displayMode`,
`outputformat`, and every show flag exactly. Treat `key` as a server-derived protected scalar: accept
only the expected string type within the strict configured size bound, then discard it unconditionally
because direct-password authentication can populate a session key that PLE did not send. Bound and
type-check server-derived `sourceFilePath`, `problemUUID`, `psvn`, `theme`, `language`, and
`extraHeaderText`, then discard them. `WWsubmit` and the radio name/value are outgoing grade-form and
body-parsed controls, never members of this hidden map. Refuse an unknown, duplicate, missing, or
mismatched member. Drop no unknown top-level member: reject it.

### Score projection

RC3 accepts only official all-or-nothing numeric percent scores exactly `0` or `100`; a string score,
non-finite value, negative value, greater-than-100 value, or fractional/partial value refuses. `0`
produces zero earned points. `100` produces exactly the published positive point value. The adapter
never derives partial credit from an upstream score in RC3.

### Choice identifier bytes

For every projected radio option, calculate SHA-256 over this exact byte sequence:

1. ASCII `ple:webwork:choice:v1\0`.
2. The `VersionId` UUID raw 16 bytes.
3. Attempt seed as unsigned 64-bit big-endian bytes.
4. Radio-group ordinal as unsigned 32-bit big-endian bytes; RC3 permits only ordinal `0`.
5. Choice ordinal as unsigned 32-bit big-endian bytes.

Use the first 16 digest bytes as 32 lowercase hexadecimal characters and prefix `ww-`. The input never
contains an upstream radio field name, radio value, label, or source text. Refuse a duplicate resulting
choice ID before creating the envelope.

### Secret and network boundary

The launcher creates `containers/.secrets/webwork_render_password` atomically, refuses a weak or
wrong-mode file, and keeps the containing directory ignored. It sets the course/user/password-file
configuration named in the decision ledger without printing the password. Compose mounts the same
secret only to API and the required WebWork initialization/application owner. The required two private
networks have exactly the membership stated in the decision ledger; the topology test treats an extra
attachment as a failure.
