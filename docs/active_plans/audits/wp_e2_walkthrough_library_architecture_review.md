# WP-E2 walkthrough library architecture review

## Verdict

ACCEPTED. The direct-Python help P2 is repaired: the shared parser now uses
the stable `run_ui_walkthrough` program name, and canonical and compatibility
Python entry points produced byte-identical help in the focused migration
check. Per the repository test-value policy, this hardcoded argparse/wiring
snapshot is one-time migration evidence rather than a permanent regression
test.

The related behavior-first naming repair is also accepted. Former plan-label
files now use `student_leave_resume_*` and `student_completion_policy_*`
names, while their schema records retain `"J3"` and `"J4"` only as serialized
journey values. The naming policy rejects new `test_j*`, `test_m*`, and
`test_w*` filename prefixes.

## Scope and ownership

- `tests/walkthrough/` is the sole owner of the canonical shell/Python
  entrypoints, fixed TypeScript children, and reusable Python implementation.
- `tests/walkthrough/walklib/__init__.py` is a one-line package docstring;
  callers import owning modules directly. It contains no re-export or logic.
- `tests/e2e/e2e_ui_walkthrough.sh` execs the canonical shell entry point.
  Its Python companion only adds the dedicated directory to `sys.path` and
  calls `walklib.runner.main`. Neither compatibility file owns lifecycle,
  configuration, or child-process behavior.
- `tests/playwright/` remains the only home for Playwright imports. The moved
  children import simulator support via `../../playwright/simulator/`, so the
  runner does not hide browser journeys or move Playwright into generic E2E.
- The runner imports only `walklib` modules. The package has no import cycle,
  import of another E2E runner, or import of a test module/test-support module.
  Offline inputs and doubles are local to their focused test modules; no shared
  walkthrough test-support fixture remains.

## Discovery, policy, and documentation

- `tests/test_ui_walkthrough_harness_independence.py` recursively scans every
  Python, shell, and TypeScript source under `tests/walkthrough/`, then scans
  the two compatibility facades and the independent Playwright journeys.
- `tests/conftest.py` excludes `walkthrough` alongside `e2e` and `playwright`.
  The existing E2E naming policy remains correctly scoped to generic
  `tests/e2e/`; the dedicated owner has a named canonical entry point.
- `docs/E2E_TESTS.md`, `docs/CODE_ARCHITECTURE.md`,
  `docs/FILE_STRUCTURE.md`, `docs/USAGE.md`, `docs/TROUBLESHOOTING.md`,
  `docs/HUMAN_GUIDANCE.md`, the active walkthrough plan, WP-E2 workstream,
  and changelog consistently describe the new owner and retained legacy
  facades. Historical evidence still names the command used at the time and
  is appropriately not rewritten.
- All new authored sources remain below the 1,000-line boundary. The
  composition root is 764 lines; configuration, contracts, models, and
  subprocess values have distinct focused owners.
