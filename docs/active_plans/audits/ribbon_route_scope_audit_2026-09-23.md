# Ribbon route-scope audit

Date: 2026-09-23

Status: Read-only screenshot and source audit. No interaction study or source changes were part of this review.

## Smallest product rule

> Tier 2 lists sibling destinations at the deepest active work scope: product collection or the active Course, Assessment, or Attempt workspace. Entering a different scope replaces the prior set. Current-object identity and return to a parent scope belong in context or breadcrumbs; progress and within-work sequences belong in the content. An empty Tier 2 is valid when there are no sibling destinations.

Tier 1 remains the stable role-level taxonomy in Human Guidance. This rule makes Tier 2's *meaning* predictable even when its destinations change: the row always answers, "Where else can I go within the work I am doing now?"

## Main finding: Tier 2 content changes while Tier 1 stays selected

Related Instructor routes can keep the same Tier 1 tab selected while replacing the task group and controls in the second Ribbon row. The shell's outer geometry is essentially stable within a viewport and density profile: the Ribbon reserves fixed top and task-row tracks, the shell grid uses that fixed Ribbon block, and the breadcrumb prelude has a fixed height ([Ribbon geometry](../../../src/ribbon/app_ribbon.css#L5), [shell tracks](../../../src/ribbon/app_ribbon.css#L49), [breadcrumb prelude](../../../src/ribbon/app_ribbon_density.css#L166)). This establishes stable row bounds and content origin in the route comparisons; it does not establish pixel-invariant positions or rendering for every control inside those rows.

What changes in Tier 2 is the content inside its reserved scrollport. The active route supplies different task-group membership, labels have different widths, and the row lays those controls out in a horizontal flex track ([row layout](../../../src/ribbon/app_ribbon.css#L87)). As a result, individual controls occupy different horizontal positions inside the same row. This is route-dependent navigation-content reflow, not general shell-geometry drift. Separately, the Instructor average visibly blurs the Tier 1 **Assessments** tab, indicating that its position shifts across captures. The average does not quantify the exact displacement; precise alignment or template matching would be needed to measure it and separate positional change from selected-state rendering. The Tier 1 tab names the role's broad work area; it does not promise that Tier 2 will retain the same destination set as the user enters a Course or Assessment workspace.

The shared source owns this behavior. Routes in [route_contract.ts](../../../src/route_contract.ts) declare `taskGroup`; for example, [Assessment creation](../../../src/route_contract.ts#L418) and [Assessment workspace](../../../src/route_contract.ts#L429) share Tier 1 but declare different task groups. [ribbon_contract.ts](../../../src/ribbon/ribbon_contract.ts#L409) derives task areas from that group, using labels defined near [TASK_AREA_LABELS](../../../src/ribbon/ribbon_contract.ts#L158). [AppRibbon](../../../src/ribbon/app_ribbon.tsx#L475) renders the brand and Tier 1 tabs in its top row, then renders the derived task areas in the same second row at [line 581](../../../src/ribbon/app_ribbon.tsx#L581). This is therefore a shared Ribbon route-model responsibility, rather than a set of local page-layout variations. The screenshots support stable shell bounds, show Tier 2 controls changing with the route, and show pixel variation in the Tier 1 **Assessments** tab; they do not establish that every individual control remains positionally or visually invariant.

## Top-level Assessments row: what the written contract says

The screenshots show the second-row `ASSESSMENTS` text as a group label, followed by **Assessments Due Soon** and **My Assessment Templates**. Source confirms the label is a non-interactive `<span>` and the two destinations are controls; `ASSESSMENTS` is not a hidden or misstyled third tab. The Course and Assessment screenshots use the same task-area rendering: a group label followed by task links.

The product authority says the Assessments Ribbon must include Due Soon and My Assessment Templates, but it does not name a tier for them ([Human Guidance](../../HUMAN_GUIDANCE.md#assessment-interface)). The more specific [Ribbon task model](../../ux/RIBBON_TASK_MODEL.md#product-frame) defines the Task Row as sibling destinations for the selected primary area and, in its [Instructor navigation table](../../ux/RIBBON_TASK_MODEL.md#instructor-product-navigation), explicitly lists these destinations under the Assessments primary tab. The [UI design guide](../../UI_DESIGN_GUIDE.md#navigation) makes the same task-row assignment. Current source follows that model: both routes select the Assessments Tier 1 area and `instructorAssessments` task group, and both catalog entries belong to that group ([routes](../../../src/route_contract.ts#L394), [task catalog](../../../src/ribbon/ribbon_catalog.ts#L331), [TaskArea rendering](../../../src/ribbon/app_ribbon.tsx#L229)). Under the scope rule above, these are product-level tasks; entering a Course or Assessment workspace replaces them with navigation local to that object.

The source follows its declared Task Row contract, and the `ASSESSMENTS` label is a non-interactive area name. Tier 1 alone does not determine the second row's contents; the selected route scope does. The distinction between product-level Assessments tasks and Course or Assessment workspaces is coherent when Tier 2 is explicitly defined as navigation for the deepest active scope.

The [Human Guidance navigation rules](../../HUMAN_GUIDANCE.md#ribbon-and-page-layout) call for a consistent Ribbon structure and predictable locations for navigation choices across related pages. *About Face*, especially its discussion of user mental models (chapter 1) and orchestration and flow (chapter 11), supports treating stable recognition and control locations as part of task flow. Here, the shell geometry and row location are stable, while route-specific Task Rows are explicitly part of the lower-level model. The usability concern is narrower: under one selected Tier 1 tab, users move between product-level and object-scoped task sets, and the duplicated Assessments label makes that scope boundary less legible; changing membership and label widths also change the controls' horizontal positions inside the fixed row. This is a heuristic concern about the product model and content continuity, not evidence of a systemic shell-layout defect or of implementation departure from its declared model.

The workspace change itself has a meaningful task distinction. Collection navigation and in-Course or in-Assessment workspaces do not have identical destinations, and the group labels, breadcrumbs and page content provide useful scope cues. The group label identifies the active Task Area; it does not replace the breadcrumb's object path. The repeated **Assessments** wording on Assessment creation remains a minor clarity issue because the top row and the Course task are both named Assessments. A route comparison is not enough to establish its effect on users, so this remains an expert heuristic finding rather than a measured usability result.

## Student Attempt navigation does not establish the same rule

The [Student Course list](../../screenshots/student/laptop/course_list.png) has Tier 1 **Courses** and no Task Row. The [Course landing](../../screenshots/student/laptop/not_started.png) changes the selected Tier 1 to Coursework and also has no task group ([route](../../../src/route_contract.ts#L219)). In active [Attempt captures](../../screenshots/student/laptop/assessment_navigation.png) across laptop, tablet, phone and square sizes, Coursework remains selected and the Task Row appears with the **ATTEMPT** area, an **Attempt** link, and **Back to Coursework**.

These controls do different work. In the active Attempt screenshot, **Attempt** names and links to the current surface; **Back to Coursework** leaves the Attempt for its Student access/overview route. On the Attempt summary route, the Attempt link can return to active work, while **Back to Coursework** still moves to the overview. The breadcrumb already identifies the Course, specific Coursework item, and current Attempt ([attempt breadcrumbs](../../../src/ribbon/ribbon_contract.ts#L657)). Question navigation and saved status stay in the content, as Human Guidance requires ([Coursework navigation](../../HUMAN_GUIDANCE.md#L664)). The current Attempt row therefore mixes object identity, a current-surface or re-entry link, and parent-scope navigation rather than a set of same-scope sibling destinations.

Human Guidance explicitly leaves Student Tier 2 unsettled ([Student navigation rule](../../HUMAN_GUIDANCE.md#L634)). The lower-level [UI design guide](../../UI_DESIGN_GUIDE.md#L213) proposes an Attempt Slot and one Task, Back to Coursework; the current source instead keeps Coursework as Tier 1 and derives an Attempt Task Area with both **Attempt** and **Back to Coursework** controls ([route](../../../src/route_contract.ts#L268), [task catalog](../../../src/ribbon/ribbon_catalog.ts#L439), [return control](../../../src/ribbon/ribbon_catalog.ts#L523)). The active [role Tier 2 decision record](../decisions/role_tier_two_navigation.md#L63) also records Student Tier 2 as empty pending a demonstrated within-context task. These lower-level choices are not a settled Student product rule.

Applying the smallest rule would keep **Attempt** identity in context/breadcrumbs and place the **Back to Coursework** return path with parent-scope navigation. On the active Attempt view, Tier 2 would remain empty unless true Attempt-scope sibling destinations are established. A summary-to-active-Attempt link would need a separate decision about whether it is a sibling workspace destination or a local re-entry action. Numbered Question navigation and saved progress remain in the Attempt content. This resolves the Student scope boundary without changing the role-level Coursework tab.

## What already works

- The row bounds and product identity appear comparatively stable in the user-supplied `average.png`, but the Tier 1 **Assessments** tab is visibly blurred, indicating positional shift across captures. Its exact displacement and any contribution from selected-state rendering remain unmeasured. The separate Tier 2 **Assessments** control also varies. The average's translucency is an averaging artifact, not a rendered application state.
- Student captures across laptop, tablet, phone and square sizes show the compact navigation adapting to viewport width while retaining the product identity, Coursework location and reachable Attempt controls.
- The scope labels, breadcrumbs and contextual page links help users recognize where a route sits, including the Blueprint detail route without a selected task destination.
- Within each captured viewport and density profile, the reserved two-row Ribbon and fixed-height breadcrumb prelude follow Human Guidance's instruction to keep row space and prevent the content area from jumping when selections change. Responsive profiles intentionally alter dimensions across device classes; the evidence supports route stability within a profile, not identical geometry across all viewports.

## Evidence limits

The four Student average images and the Instructor average are user-generated diagnostic composites made by averaging screenshots in their respective folders. The Instructor average shows positional variation in the Tier 1 **Assessments** tab, but does not quantify its displacement or isolate any additional effects from selected-state styling or theme; precise alignment or template matching would be needed for that. Overlaying controls is an averaging artifact, not a rendered application state. The Student route comparison is available at four viewport sizes; the Instructor screenshot corpus is 1280 px wide, so it does not establish how Tier 2 or the top row behaves at narrower Instructor widths. These are static captures, not recordings of transitions, keyboard navigation, focus movement or user performance.

## Audit conclusion

The smallest predictable rule is scope-relative sibling navigation: Tier 2 follows the deepest active work scope and changes destination sets when that scope changes. This makes the Instructor collection-to-Course-to-Assessment replacements coherent. Student Attempt currently uses Tier 2 for current-object identity and a parent return, while Human Guidance leaves Student Tier 2 unsettled; the active Attempt row does not match the proposed sibling-destination rule. No Ribbon source was changed.
