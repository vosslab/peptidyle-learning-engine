## Accepted boundaries

- RC8 uses the PLE passwordless/account/session graph in production. Local-file
  login is selected only by the exact development flag and cannot substitute
  for canonical onboarding.
- The stable shell entrypoint delegates to typed Python `argparse`. AUTO reuses
  only regular readable non-symlink `dist/index.html` and `dist/main.js`, then
  builds otherwise; `--build` forces a rebuild and `--skip-build` fails before
  report or Podman work without both outputs. The gateway is IPv4
  `127.0.0.1`; no IPv6 support is required or claimed.
- Runner cleanup is ownership-scoped and uses `down --remove-orphans` without
  volume removal. Reports are canonical ASCII JSON in a mode-0700 directory
  with a mode-0600 regular file. Credentials, answers, scores, child output,
  traces, screenshots, videos, and private state do not enter reports.
- Arrangement uses supported authenticated APIs and reports five named
  arrangements. There is no simulator SQL, enrollment/account fixture, direct
  route, browser-state, or product-source workaround. The non-keyboard
  arranged inspection is arrangement evidence, not a walked journey.
- The Rust retry repair supplies the committed predecessor; the frontend uses
  the receipt as authority for completion and successor transition and remounts
  response controls for a distinct attempt while preserving same-attempt
  recovery.
- J1 through J5 and J8 retain manager and independently accepted retained-stack
  forced-build live evidence with only visible platform-path codes. They do not
  reconstruct correctness or scores. The fresh seed-42 report is schema-v1
  `PASS` at `complete`, contains exactly the five arrangements and ordered six
  journey rows, and has empty diagnostics.
- J3/J4/J5/J8 use a fixed private six-row serial state contract. The mode,
  no-symlink, descriptor, ASCII, canonical JSON, ordering, public-ID, and
  bounded-size checks fail closed. J8 derives only from public J4/J5 evidence;
  the final renderer rejects reordered, incomplete, hidden, symbolic, and
  answer-like records.
- The resolved retained-volume pagination is product behavior, not simulator
  accommodation. `CursorPageSession` serializes opaque continuation cursors,
  preserves transport retry, deduplicates items, and stops on invalid repeated
  or zero-new nonterminal pages. Course and gradebook controls use visible
  `target="_self"` fragment links, one native Tab to a real action, status and
  recovery messages, and focus transfer to the first appended public control.
  The gradebook is keyed to the active route course and discards delayed former
  course results before render or focus transfer.
- G1 static harness independence, refreshed duplicate-safe G2 baseline, and
  G3 documentation are consistent with the implementation and its limits.

## Validation

Passed in this re-review: 1,820 focused pytest checks plus 3 subtests; 36 Node
contract tests; strict TypeScript; ESLint; Prettier; shell syntax; Python
compilation and Pyflakes; MemoryStore 51-record pagination conformance; and
`git diff --check`. The independent retained-volume live report is inspected
directly: the directory is `drwx------`, its sole report is `-rw-------`, and
the report contains no credential, answer, score, trace, screenshot, video,
or private-state field. No live stack was started by this reviewer; `podman ps
--all --quiet` was empty and no walkthrough temporary root remained.

A local rerun of fixture-only Playwright pagination tests could not launch
Chromium because the sandbox denied macOS Mach-port registration before browser
creation. That is environment evidence, not a product failure; the accepted
browser evidence is the independent retained-volume forced-build run and the
recorded focused browser validations. The generated fixture diagnostics were
removed immediately. No source or documentation change was made outside this
audit.
