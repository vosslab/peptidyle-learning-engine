## Decision and coverage method

The approved contract makes four modes (Compact, List, Cards, Visual Boxes) the normal
outcome for every collection. At the M02 baseline, `RecordList` had three modes;
the later shared four-mode implementation and its accepted integration evidence are
recorded in [datasheet_collection_status.md](datasheet_collection_status.md).
Different fields, direct actions, or visual density are not exceptions.

Each row below is one distinct user-facing record-bearing workflow. A reusable component
can occur in several rows when its caller gives it a different scope, owner, or workflow.
The source census found 37 `SearchBlock`, 32 record-family, and 25 picker-pattern source hits
(94 total). They are call-pattern hits, not collection counts: the picker and record patterns also
match generic type syntax and shared implementation. The hit reconciliation below assigns every
one either to a cataloged workflow or to the shared component that renders its cataloged callers.
After tracing component callers, route branches, nested detail, and custom lists, this inventory
assigns 71 user-facing record-bearing workflows: 67 contain one or more collections subject to
DataSheetBlock and all four presentation modes; 4 are noncollection task views. Each workflow is
counted once; hybrid rows name their document wrapper and collection surface.

At the M02 baseline, `local` meant the complete authorized resource was already in
the browser; `remote` named the API/store/SQL boundary responsible for predicate,
total, order, and page selection. "Cursor now" describes that baseline. M06-M12
subsequently established the accepted local and remote contracts.

## M02 baseline findings that constrained later milestones

- `SearchBlock` composes controls with `SearchResults`, which always renders `RecordList`; its
  direct caller retains query and workflow state. M13 must extract the shared display without
  moving domain scope or commands out of callers.
- `createLocalCompleteSearch` already performs browser filtering/sorting before its cursor slice,
  prunes selection after its source resource changes, and exposes explicit refresh. M05 must use
  actual mutation and resource origins to decide refresh: current-interface commands update the
  affected resource; another tab does not autosynchronize a snapshot.
- Current `SearchResults` exposes cursor Previous/Next only. M06 owns numbered `pageNumber`,
  `pageSize`, `totalCount`, and deterministic transitions. M07-M12 own their remote query paths.
- The M07 Library/picker repair is mandatory where eligibility/exclusion is post-page: apply the
  same eligibility predicate before count and page selection. This includes C03 and C05-C09/C13/C17
  when they query remote Library content.
- Assessment ordered content (C12, C14-C16) is an applicable collection but has one functional
  query-operation constraint: display sort stays disabled because saved order is the domain record;
  reorder uses stable entry IDs and full positions. This does not waive modes, direct actions, or
  independent panel state.
- All 67 collection-bearing workflows use Compact, List, Cards, and Visual Boxes. Actual operation
  constraints such as saved order, recovery radio choice, and privacy remain in force without
  disabling a presentation mode; C61-C63 and C71 are the four noncollection task views.
